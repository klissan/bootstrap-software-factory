# bootstrap-software-factory

Скилл для ИИ-агента (Claude Code, Cursor): обследует ваши репозитории, существующую ИИ-обвязку, CI и интеграции
и собирает под проект «фабрику» разработки и, по желанию, расследования инцидентов: workflows, роли, скрипты-инструменты,
журналы решений. Повседневная работа дальше идёт по созданным `AGENTS.md`, workflows и скриптам, а не через этот скилл.

Поддерживает рантаймы Claude Code, Codex и Cursor (основной и ревьюер могут быть разными, с разными моделями) и хостинг/трекеры:
GitHub, GitLab (self-managed), Forgejo, Bitbucket Data Center, Jira Cloud, Jira Data Center.

## Что внутри

```
skills/bootstrap-software-factory/
  SKILL.md        ядро: принципы, порядок фаз, правила журнала решений
  references/     24 файла, читаются по необходимости (провайдеры, рантаймы, онбординг, рекомендуемые инструменты, скрипты, защитные проверки, проверки)
```

## Установка

Скилл — это папка `skills/bootstrap-software-factory` целиком (`SKILL.md` + `references/`). Скопируйте её в каталог скиллов.

```bash
git clone git@github.com:klissan/bootstrap-software-factory.git
```

### Claude Code

Для всех проектов (личный скилл), PowerShell:

```powershell
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse bootstrap-software-factory\skills\bootstrap-software-factory "$HOME\.claude\skills\"
```

bash / zsh:

```bash
mkdir -p ~/.claude/skills
cp -r bootstrap-software-factory/skills/bootstrap-software-factory ~/.claude/skills/
```

Только для одного проекта: скопируйте папку в `<проект>/.claude/skills/` (можно закоммитить, чтобы скилл был у всей команды).

### Cursor

Cursor находит скиллы в `.cursor/skills/` и `.agents/skills/` проекта, в `~/.cursor/skills/` и `~/.agents/skills/` пользователя,
а для совместимости и в `.claude/skills/` и `~/.claude/skills/`. Поэтому есть два пути:

- уже поставили скилл для Claude Code в `~/.claude/skills/` — Cursor его увидит, ничего больше делать не нужно;
- иначе скопируйте папку в `~/.cursor/skills/` (все проекты) или `<проект>/.cursor/skills/` (один проект), теми же командами, заменив каталог назначения.

Источник: документация Cursor, раздел Skills (cursor.com/docs/skills); для Claude Code — code.claude.com/docs/en/skills.
Для Codex и других агентов сверьтесь с документацией установленной версии.

Если скилл не виден, проверьте, что `SKILL.md` лежит прямо в `<каталог скиллов>/bootstrap-software-factory/`, и перезапустите сессию.

## Как запустить

Откройте агента в каталоге будущей фабрики и напишите минимально:

```text
Используй bootstrap-software-factory. Поехали.
```

Или подробнее (обязательных пунктов нет: о недостающем скилл спросит сам):

```text
Используй bootstrap-software-factory.
Фабрика: <каталог или репозиторий фабрики>.
Репозитории:
- <путь или URL> — <роль одной строкой>
- <путь или URL> — <роль одной строкой>
Трекер: <Jira Cloud / Jira DC / GitHub / ...>, <URL экземпляра>.
Хостинг кода: <GitHub / GitLab / Bitbucket DC / Forgejo>, <URL экземпляра>.
Основной агент (где идёт работа): <Claude Code / Codex / Cursor>.
Ревьюер: <агент>, модель <модель>.
Процессы: <разработка / инциденты / оба>.
Разрешённые внешние записи: <например: создавать задачи, пушить ветки, открывать PR>.
Точка завершения: <локальные изменения / PR / merge>.
Нельзя трогать: <железо, секреты, production, ...>.
```

Секреты в сообщение не вставляйте: скилл подскажет, где создать токен и в какой конфиг или переменную окружения его положить.

## Что будет дальше

- Обследование репозиториев, обвязки, CI и доступных интеграций.
- Короткие раунды вопросов только о том, что не удалось выяснить.
- Инструкции по настройке токенов и инструментов и скрипт их проверки (печатает только пройдено/не пройдено, значений не показывает).
- Короткий список рекомендуемых плагинов и MCP-серверов (например, Context7): каждый пункт отдельно, ставится только с вашего согласия.
- Защитные проверки (guards): скрипты на системном шелле, которые по инвариантам проекта не дают агенту сделать запрещённое (например, правка защищённого файла или публикация без пройденной проверки), и подключение их к хукам Claude Code, Cursor и Codex. Честно помечено, где блокировка жёсткая, а где совещательная.
- Вопросы о рабочих соглашениях: как публиковать ревью (комментарии в PR, одно резюме или только локально, тогда PR создаётся уже отревьюенным), нужно ли двигать тикеты и по каким правилам называть ветки, коммиты и заголовки PR. Всё это решаете вы, по умолчанию тикеты не двигаются.
- Ревью прямо в дифф: режим `inline`, по ветке обсуждения на находку, с ответами и резолвом (GitLab, GitHub; Bitbucket и Forgejo проверяются при бутстрапе).
- Эпики на несколько репозиториев: анализ, декомпозиция, согласование плана с вами до создания тикетов, идемпотентное создание дочерних тикетов и сводка состояния.
- Генерация конфигурации, workflows, скриптов (всё рутинное, где не нужен интеллект, — скриптами) и журналов решений.
- Проверка на тестовых репозиториях и отчёт о том, что реально проверено, а что нет.

В конце скилл советует открыть **новую** сессию в каталоге фабрики и печатает точную первую команду: состояние хранится в файлах, а не в переписке.

## Когда скилл нужен снова

Аудит, обновление фабрики, новый репозиторий, провайдер или агент, перенос накопленных уроков в скилл. Для повседневной работы он не нужен:
фабрика работает без него, и его можно оставить, вынести в личный каталог скиллов или удалить из репозитория фабрики.

Подробности — в `skills/bootstrap-software-factory/SKILL.md` и `references/`.
